= Java Programmier-Cheatsheet
:toc:
:toclevels: 2
:sectanchors:

Dieses Cheatsheet dient als schnelle Orientierungshilfe.
Verwende es, wenn du dich an das Thema erinnerst, aber nicht mehr an den genauen Begriff.
Für vollständige Erklärungen führen die Links zu den drei Glossaren.

== Programmstruktur

[cols="1,3,3",options="header"]
|===
|Begriff |Typische Java-Syntax |Kurzbeschreibung

|xref:01_JAVA_BASICS.adoc#jb-source-code[Quellcode (source code)]
|`*.java`
|Für Menschen lesbarer Java-Programmtext.

|xref:01_JAVA_BASICS.adoc#jb-package[Package]
|`package ch.school.example;`
|Gruppiert zusammengehörige Typen in einem Namensraum.

|xref:01_JAVA_BASICS.adoc#jb-import[Import]
|`import java.util.List;`
|Macht einen Typ oder ein statisches Member unter einem kürzeren Namen verfügbar.

|xref:02_OBJECT_ORIENTED_PROGRAMMING.adoc#oop-class[Klasse (class)]
|`class Car { ... }`
|Definiert einen Referenztyp sowie Struktur und Verhalten seiner Objekte.

|xref:01_JAVA_BASICS.adoc#jb-main-method[Main-Methode (main method)]
|`public static void main(String[] args)`
|Üblicher Einstiegspunkt einer Java-Anwendung.

|xref:01_JAVA_BASICS.adoc#jb-block[Block]
|`{ ... }`
|Gruppiert Anweisungen und definiert normalerweise einen lokalen Gültigkeitsbereich.

|xref:01_JAVA_BASICS.adoc#jb-statement[Anweisung (statement)]
|`total = price * amount;`
|Eine vollständige Instruktion oder Kontrollflusseinheit.

|xref:01_JAVA_BASICS.adoc#jb-expression[Ausdruck (expression)]
|`price * amount`
|Code, der ausgewertet wird und einen Wert oder ein Ergebnis erzeugt.
|===

== Namenskonventionen

[cols="2,2,3,3",options="header"]
|===
|Java-Element |Konvention |Beispiel |Hinweis

|Klasse
|xref:01_JAVA_BASICS.adoc#jb-pascal-case[PascalCase]
|`BankAccount`
|Substantive sind häufige Klassennamen.

|Interface
|xref:01_JAVA_BASICS.adoc#jb-pascal-case[PascalCase]
|`Printable`
|Beschreibt häufig eine Fähigkeit oder Rolle.

|Record
|xref:01_JAVA_BASICS.adoc#jb-pascal-case[PascalCase]
|`CustomerAddress`
|Verwendet denselben Benennungsstil wie Klassen.

|Enum-Typ
|xref:01_JAVA_BASICS.adoc#jb-pascal-case[PascalCase]
|`OrderStatus`
|Enum-Konstanten selbst verwenden normalerweise UPPER_SNAKE_CASE.

|Methode
|xref:01_JAVA_BASICS.adoc#jb-camel-case[camelCase]
|`calculateTotal()`
|Ein Verb oder eine Verbphrase ist üblich.

|Variable
|xref:01_JAVA_BASICS.adoc#jb-camel-case[camelCase]
|`numberOfStudents`
|Beschreibt die Bedeutung des Werts und nicht nur seinen Typ.

|Parameter
|xref:01_JAVA_BASICS.adoc#jb-camel-case[camelCase]
|`maximumSpeed`
|Verwendet dieselbe Konvention wie lokale Variablen.

|Konstante
|xref:01_JAVA_BASICS.adoc#jb-upper-snake-case[UPPER_SNAKE_CASE]
|`MAX_SPEED`
|Wird häufig für `static final`-Konstanten verwendet.

|Package
|xref:01_JAVA_BASICS.adoc#jb-lowercase[lowercase]
|`ch.school.examples`
|Normalerweise kleingeschrieben, häufig basierend auf einer umgekehrten Domain-/Firmenstruktur.
|===

NOTE: xref:01_JAVA_BASICS.adoc#jb-snake-case[snake_case] ist in anderen Technologien ein verbreiteter Namensstil, wird aber normalerweise nicht für gewöhnliche Java-Variablen oder -Methoden verwendet.

== Variablen und Datentypen

[cols="2,2,5",options="header"]
|===
|Begriff |Beispiel |Kurzbeschreibung

|xref:01_JAVA_BASICS.adoc#jb-variable[Variable]
|`int age = 18;`
|Ein benannter Speicherort mit einem zur Compile-Zeit bestimmten Typ.

|xref:01_JAVA_BASICS.adoc#jb-declaration[Deklaration (declaration)]
|`int age;`
|Führt dem Compiler ein Programmelement ein.

|xref:01_JAVA_BASICS.adoc#jb-initialization[Initialisierung (initialization)]
|`int age = 18;`
|Gibt einer Variable ihren ersten Wert.

|xref:01_JAVA_BASICS.adoc#jb-assignment[Zuweisung (assignment)]
|`age = 18;`
|Speichert einen Wert in einer Variable.

|xref:01_JAVA_BASICS.adoc#jb-reassignment[Neuzuweisung (reassignment)]
|`age = 19;`
|Weist nach einem früheren Wert einen neuen Wert zu.

|xref:01_JAVA_BASICS.adoc#jb-primitive-type[Primitiver Datentyp (primitive type)]
|`int`, `double`, `boolean`
|Einer der acht eingebauten Nicht-Referenztypen von Java.

|xref:01_JAVA_BASICS.adoc#jb-reference-type[Referenzdatentyp (reference type)]
|`String`, `Car`, `int[]`
|Typ, dessen Werte auf Objekte oder Arrays verweisen oder `null` sind.

|xref:01_JAVA_BASICS.adoc#jb-wrapper-class[Wrapper-Klasse (wrapper class)]
|`Integer`, `Double`
|Objektrepräsentation, die einem primitiven Datentyp entspricht.

|xref:01_JAVA_BASICS.adoc#jb-var[Var]
|`var name = "Ada";`
|Typinferenz für lokale Variablen; Java bleibt statisch typisiert.

|xref:01_JAVA_BASICS.adoc#jb-final[Final]
|`final int max = 10;`
|Verhindert Neuzuweisung oder in anderen Kontexten Überschreiben bzw. Erweitern.

|xref:01_JAVA_BASICS.adoc#jb-casting[Casting]
|`(int) 3.9`
|Fordert explizit eine kompatible Typumwandlung an.

|xref:01_JAVA_BASICS.adoc#jb-scope[Gültigkeitsbereich (scope)]
|`{ int x = 1; }`
|Quellcodebereich, in dem ein deklarierter Name sichtbar ist.
|===

== Operatoren und Programmablauf

[cols="2,3,5",options="header"]
|===
|Begriff |Beispiel |Kurzbeschreibung

|xref:01_JAVA_BASICS.adoc#jb-arithmetic-operator[Arithmetischer Operator]
|`+ - * / %`
|Führt numerische Berechnungen aus.

|xref:01_JAVA_BASICS.adoc#jb-comparison-operator[Vergleichsoperator]
|`== != < <= > >=`
|Vergleicht Werte und erzeugt `boolean`.

|xref:01_JAVA_BASICS.adoc#jb-logical-operator[Logischer Operator]
|`&& \|\| !`
|Verknüpft oder negiert boolesche Werte.

|xref:01_JAVA_BASICS.adoc#jb-if[If]
|`if (condition) { ... }`
|Führt einen Zweig aus, wenn eine Bedingung wahr ist.

|xref:01_JAVA_BASICS.adoc#jb-else[Else]
|`else { ... }`
|Alternativer Zweig, wenn das zugehörige `if` falsch ist.

|xref:01_JAVA_BASICS.adoc#jb-switch[Switch]
|`switch (value) { case 1: ... break; default: ... }` +
`switch (value) { case ... -> ...; default -> ...; }`
|Zwei Schreibweisen einer switch-Anweisung. Wählt mit `case` zwischen mehreren Zweigen; `default` behandelt Werte, die zu keinem anderen Case passen.

|xref:01_JAVA_BASICS.adoc#jb-for[For]
|`for (int i = 0; i < 10; i++) { ... }` +
`for (String name : names) { ... }`
|Wiederholt Code entweder mit einer klassischen Zählschleife oder mit einer erweiterten for-Schleife über Elemente.

|xref:01_JAVA_BASICS.adoc#jb-while[While]
|`while (condition) { ... }`
|Kopfgesteuerte Schleife.

|xref:01_JAVA_BASICS.adoc#jb-do[Do]
|`do { ... } while (condition);`
|Fussgesteuerte Schleife, die mindestens einmal ausgeführt wird.

|xref:01_JAVA_BASICS.adoc#jb-break[Break]
|`break;`
|Verlässt die nächstgelegene Schleife oder eine klassische switch-Anweisung.

|xref:01_JAVA_BASICS.adoc#jb-continue[Continue]
|`continue;`
|Springt zur nächsten Schleifeniteration.
|===

== Vererbung, Interfaces und Polymorphismus

[cols="2,3,5",options="header"]
|===
|Begriff |Beispiel |Kurzbeschreibung

|xref:02_OBJECT_ORIENTED_PROGRAMMING.adoc#oop-extends[Extends]
|`class Dog extends Animal`
|Erzeugt eine Vererbungsbeziehung zwischen Klassen.

|xref:02_OBJECT_ORIENTED_PROGRAMMING.adoc#oop-super[Super]
|`super.method()`
|Greift aus einem Instanzkontext auf Verhalten der direkten Superklasse zu.

|xref:02_OBJECT_ORIENTED_PROGRAMMING.adoc#oop-super-constructor[Superkonstruktor-Aufruf (super constructor invocation)]
|`super(name);`
|Ruft einen Konstruktor der direkten Superklasse auf.

|xref:02_OBJECT_ORIENTED_PROGRAMMING.adoc#oop-implements[Implements]
|`class Dog implements Trainable`
|Deklariert die Implementierung eines Interface-Vertrags.

|xref:02_OBJECT_ORIENTED_PROGRAMMING.adoc#oop-abstract-class[Abstrakte Klasse (abstract class)]
|`abstract class Animal`
|Kann nicht direkt instanziiert werden; kann gemeinsames und abstraktes Verhalten kombinieren.

|xref:02_OBJECT_ORIENTED_PROGRAMMING.adoc#oop-runtime-polymorphism[Laufzeitpolymorphismus (runtime polymorphism)]
|Method overriding
|Der tatsächliche Objekttyp bestimmt zur Laufzeit, welche überschriebene Methodenimplementierung ausgeführt wird.

|xref:02_OBJECT_ORIENTED_PROGRAMMING.adoc#oop-method-overriding[Method Overriding (Methodenüberschreibung)]
|`@Override`
|Eine Subklasse stellt eine neue Implementierung einer geerbten Methode bereit.

|xref:02_OBJECT_ORIENTED_PROGRAMMING.adoc#oop-compile-time-polymorphism[Compile-Time-Polymorphismus (compile-time polymorphism)]
|Method overloading
|Der Compiler bestimmt anhand der Methodensignatur und der Argumente an der Aufrufstelle, welche Methodenimplementierung verwendet wird.

|xref:02_OBJECT_ORIENTED_PROGRAMMING.adoc#oop-method-overloading[Method Overloading (Methodenüberladung)]
|`print(int value)` +
`print(String value)`
|Mehrere Methoden besitzen denselben Namen, aber unterschiedliche Parameterlisten. Der Compiler bestimmt, welche Methode aufgerufen wird.

|xref:02_OBJECT_ORIENTED_PROGRAMMING.adoc#oop-upcasting[Upcasting]
|`Animal a = new Dog();`
|Betrachtet einen Subtyp über eine Referenz des Supertyps.

|xref:02_OBJECT_ORIENTED_PROGRAMMING.adoc#oop-downcasting[Downcasting]
|`Dog d = (Dog) a;`
|Fordert explizit einen spezifischeren Referenztyp an.

|xref:02_OBJECT_ORIENTED_PROGRAMMING.adoc#oop-instanceof[Instanceof]
|`a instanceof Dog`
|Prüft die Typkompatibilität zur Laufzeit.

|xref:02_OBJECT_ORIENTED_PROGRAMMING.adoc#oop-dynamic-dispatch[Dynamic Dispatch]
|`a.makeSound()`
|Das Laufzeitobjekt bestimmt die überschriebene Methodenimplementierung.
|===

== Designprinzipien und Design Patterns

[cols="2,3,5",options="header"]
|===
|Begriff |Kurzform |Kurzbeschreibung

|xref:03_ADVANCED_JAVA_CONCEPTS.adoc#adv-kiss[KISS]
|Keep It Simple
|Vermeide unnötige Komplexität.

|xref:03_ADVANCED_JAVA_CONCEPTS.adoc#adv-dry[DRY]
|Don't Repeat Yourself
|Vermeide dupliziertes Wissen und doppelte Regeln.

|xref:03_ADVANCED_JAVA_CONCEPTS.adoc#adv-yagni[YAGNI]
|You Aren't Gonna Need It
|Baue spekulative Funktionen nicht zu früh.

|xref:03_ADVANCED_JAVA_CONCEPTS.adoc#adv-srp[SRP]
|Single Responsibility Principle
|Gib einer Klasse oder einem Modul einen fokussierten Grund für Änderungen.

|xref:03_ADVANCED_JAVA_CONCEPTS.adoc#adv-ocp[OCP]
|Open/Closed Principle
|Bevorzuge Erweiterungen, ohne stabilen Code wiederholt ändern zu müssen.

|xref:03_ADVANCED_JAVA_CONCEPTS.adoc#adv-lsp[LSP]
|Liskov Substitution Principle
|Subtypen müssen das erwartete Verhalten ihres Supertyps erhalten.

|xref:03_ADVANCED_JAVA_CONCEPTS.adoc#adv-isp[ISP]
|Interface Segregation Principle
|Zwinge Clients nicht, von Operationen abhängig zu sein, die sie nicht benötigen.

|xref:03_ADVANCED_JAVA_CONCEPTS.adoc#adv-dip[DIP]

== Reservierte und spezialisierte Wörter, die hier nicht benötigt werden

* `const` und `goto`: reservierte Java-Schlüsselwörter, die von der Java-Sprache nicht verwendet werden.
* `strictfp`: reserviert, aber obsolet; sollte in neuem Java-Code nicht verwendet werden.
* `native`, `synchronized`, `transient`, `volatile`: gültige spezialisierte Schlüsselwörter, aber ausserhalb dieses Lernprojekts.
* Kontextabhängige Schlüsselwörter des Java-Modulsystems wie `module`, `requires`, `exports`, `opens`, `uses` und `provides`: gültige Java-Syntax, aber ausserhalb dieses Lernprojekts.
