= Interfaces and Abstract Classes Exercises

The exercises in this file use `README.adoc` and the Java files in this package.
The optional `DEEP_DIVE.adoc` material is not required.

== Check Your Understanding

. Can an abstract class be instantiated directly?

    nein,weil eine abstrakte Klasse unvollständig ist.
    Eine Unterklasse kann aber davon erben.

. Can an abstract class have a constructor?

    Ja, eine abstrakte Klasse kann einen Konstruktor haben, der von Unterklassen aufgerufen werden kann.

. Can an abstract class contain concrete methods?

    ja, eine abstrakte Klasse kann konkrete Methoden mit Implementierung und abstrakte Methoden ohne Implementierung enthalten.

. What does an interface contract require from an implementing class?

    Eine Schnittstelle legt fest, welche Methoden eine implementierende Klasse bereitstellen muss.

. Can a class implement more than one interface?

    ja, eine klasse kann mehrer Interfaces implementieren, sie kann nur eine klasse mit extends erben.

. Why is `@Override` useful?

    Es zeigt an, dass die Methode überschrieben oder implementiert wird.
    Der Compiler kann dadurch Fehler erkennen.

. When might an interface be preferable to an abstract class?

    Ein Interface nutzt man, wenn man verschiedene Klassen hat mit dem gleichen Verhalten.
    Eine abstrakte Klasse nutzt man, wenn man gemeinsame Zustände hat oder den gleichen Code teilt.

== Mark the Code

In the Java files, identify:

* one abstract class;

    abstract class Animal

* one abstract method;

    abstract void makeSound()

* one concrete method in the abstract class;

    void printName() {
        System.out.println();
    }

* one interface;

    interface Trainable

* one `extends` relationship;

    class Dog extends Animal

* one `implements` relationship;

    class Dog .... implements Trainable

* two methods annotated with `@Override`.

     @Override
    public void makeSound(){}
    @Override
    public void performTrick(){}

== Extend the Example

Create a `Horse` class that extends `Animal` and implements `Trainable`.
Give it different implementations of `makeSound()` and `performTrick()`.

== Design Question

You are modeling `Printable`, `Invoice`, and `Photo`.
Would `Printable` be more naturally represented as a superclass or an interface?
Explain your choice using the idea of a behavioral contract.

    Printable ist ein Interface. Es beschreibt einen Verhaltensvertrag, den unterschiedliche Klassen erfüllen.
    Diese Klassen müssen keine gemeinsame Oberklasse haben.
